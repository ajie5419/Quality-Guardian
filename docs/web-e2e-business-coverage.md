## 12. 运行架构设计决策与已知限制

### 12.1 workers: 1 串行执行的已知限制与理由

Playwright 配置当前设定 `workers: 1` 串行执行用例。代码审查提出此举可能遮蔽多 worker 并发冲突。

- **暂不开启多 worker 的理由**：当前每个测试生命周期共享同一运行的隔离数据库与预置账号体系。若简单提升 `workers`，多用例并发写入会引发全局数据竞争、自增 ID 抢占及状态污染；真正在多 worker 下安全并行，需要为每个 worker 动态切分专属数据空间与账号命名空间，这属于下一阶段的测试基础设施能力。
- **现状已覆盖并发语义**：虽然 Playwright 顶层是单 worker 串行调度，但在每个涉及并发写、丢失响应重试、CAS 乐观锁与唯一键防重的用例内部，均已显式采用 `Promise.all` 发起真实并发 HTTP 请求，覆盖了后端在并发竞争下的状态机守卫与数据完整性。
- **状态**：记为已知限制与技术债，不包装为已解决。

### 12.2 源码指纹自动化采集规则

此前 `scripts/e2e/run.mjs` 中的 `sourceFiles` 采用手工列举上百个文件的方式，存在新增业务文件漏登记导致指纹漂移的缺陷。现已重构为全自动采集机制：

- **根路径集合**：配置覆盖所有直接影响 E2E 判定的业务代码根目录（`apps/backend/api`、`apps/backend/modules`、`apps/backend/middleware`、`apps/backend/plugins`、`apps/backend/prisma`、`apps/backend/routes`、`apps/backend/scripts`、`apps/backend/utils`、`apps/web-antd/e2e`、`apps/web-antd/src`、`packages/qgs-shared/src`、`packages/qgs-shared/dist`、`scripts/e2e`、`internal/vite-config/src` 等核心配置文件）。
- **递归采集与排除**：对上述根路径进行递归遍历，自动严格排除 `.git`、`.nuxt`、`.output`、`.turbo`、`coverage`、`node_modules`、`output`、`playwright-report`、`test-results` 以及 `.env*` 敏感文件。
- **白名单扩展名与确定性排序**：仅采集 `.cjs`、`.css`、`.js`、`.json`、`.md`、`.mjs`、`.mts`、`.prisma`、`.ts`、`.vue`、`.yaml`、`.yml` 等源码资产，去重后做确定性字母升序排列，逐一计算 SHA256 并生成 `sourceSha256` 证据，杜绝漏登记与平台差异。
