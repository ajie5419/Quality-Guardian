# 数据生命周期设计（Data Lifecycle）

> 权威文档：2026-08-17 成文（讨论定稿）。业务口径：**业务数据至少保留 10 年**；审计日志 3 个月；历史数据只读查询；到期处置人工确认（续留/销毁/导出三选一）。
> 关联：docs/scheduler-design.md（cron 框架）、docs/metrics-registry.md（物化表独立保留）、docs/permission-module.md（归档查看权限）。

---

## 1. 生命周期五阶段模型

创建 → 活跃使用 → 完结 → 归档（温） → 保留期满 → 人工处置（续留/销毁/导出）

| 阶段 | 状态 | 数据表现 |
| --- | --- | --- |
| 活跃 | 现行 | archivedAt 为空，可增删改查 |
| 归档 | 温 | archivedAt 有值，**只读查询** |
| 期满 | 待决策 | retainUntil 到期，进入评估清单 |
| 处置 | 终态 | 续留（更新 retainUntil）/ 销毁（软删+审计）/ 导出（OSS 交付） |

## 2. 保留期登记（业务口径 2026-08-17 确认）

| 数据类 | 保留期 | 处置 |
| --- | --- | --- |
| 检验记录、不合格品、报检任务、计量、售后、质量损失、工单 | **至少 10 年** | 归档（打标记），满 10 年进入到期评估 |
| 文件附件（OSS） | 随业务记录 10 年 | 不删，可整批转冷存储省成本 |
| 审计日志 audit_logs / login_logs | **3 个月** | 到期直接删除（cron 每日清理） |
| 物化快照/索引（quality_loss_index、评分快照等） | 1-2 年 | 到期删除，**可重建**（源数据在） |
| 临时文件/失败上传残件 | 30 天 | 清理 |

## 3. 归档机制设计

### 3.1 选型：打标记（archivedAt），不拆表

- 现状存储 6.79GB，单表撑 10 年无压力（估算：日均 200 条 × 365 × 10 ≈ 73 万行/表）
- 单表超 500 万行后再评估：分区表（按月 DROP PARTITION）或独立归档表
- 新增字段：archivedAt（DateTime?）、retainUntil（DateTime?）

### 3.1b 归档覆盖（2026-08-17 方案 B：7/7 全覆盖 + 存量兜底）

- 7 类业务表全覆盖：quality_records / inspections / qms_inspection_requests / measuring_instruments / after_sales / quality_losses / work_orders（后 4 类 2026-08-17 补字段）
- **兜底推算**：retainUntil 为空的历史数据，按 createdAt + 规则天数自动推算到期（无需逐表回填标签；创建链路显式回填保留，显式优先）
- 真实库验证：270 条无标签老工单自动归档 ✓，近期数据正确跳过 ✓

### 3.2 执行：cron 队列化（复用现有 scheduler + quality_loss_index_jobs 模式）

```
每日 02:00 data-lifecycle.daily-archive
  → 扫描候选（retainUntil 已到且 archivedAt 为空）
  → 写入归档任务表（PENDING，幂等 upsert）
  → worker 逐个处理（attempts + availableAt 重试）
  → 完成记录 + 审计日志
```

- 归档任务表：data_lifecycle_jobs（id/source/sourcePk/status/attempts/availableAt/reason）
- 处置分支：业务数据→打标记；审计日志→删除；快照→删除；临时文件→清理

### 3.3 边界处理

1. **查询路径**：列表页加数据范围筛选（默认仅现行），归档行显示徽标
2. **统计口径**：归档数据不进统计；物化表独立保留期，不随源数据归档
3. **文件联动**：归档记录附件不删，可整批转 OSS 冷存储
4. **权限**：归档查看复用现有数据权限（检验记录 10 年保留即供追溯）
5. **审计**：归档/清理动作入 audit_logs（谁/何时/处理多少条）

## 3.5 年份查询与归档的关系（2026-08-17 决策）

年份查询（不合格项/售后/质量损失按业务日期年份过滤）与归档（按创建时间+保留期）是两个维度：

| 场景 | 行为 | 原因 |
| --- | --- | --- |
| 列表页（日常视图） | 默认仅现行，含归档开关 | 日常操作只看现行 |
| **年份查询/年份统计** | **不过滤归档，归档数据仍可见/计入** | 年份查询即追溯场景；10 年保留供追溯；历史年份数字不得因归档变化 |
| 物化表统计 | 独立保留，不受源数据归档影响 | 快照/索引可重建且独立保留期 |

**实现提醒**：将来给列表页加 archivedAt 过滤（仅现行）时，不得将同一过滤加入年份查询/年份统计路径（inspection-issue-list 的 year 过滤、after-sales stats、quality-loss 统计等）。当前代码年份查询无 archivedAt 过滤，符合本决策，无需改动。
## 4. 归档查询（历史数据只读）

| 能力 | 现行 | 归档 |
| --- | --- | --- |
| 列表 | 默认可见 | 含归档筛选开启后可见（行带徽标） |
| 详情 | 可看可改 | **只读**（编辑/删除/流转禁用） |
| 导出 | 支持 | 支持（追溯交付用） |
| 统计 | 参与 | 不参与（走物化表） |

## 5. 到期处置流程（人工确认，默认保守）

```
到期前 90 天：cron 预警 → 生成到期评估清单（数据类/条数/最后活跃/负责人）
负责人决策（管理界面）：
  续留 N 年 → 更新 retainUntil（记录续留次数）
  销毁     → 二次确认（原因 + 确认框）→ 软删 + 审计
  导出交付 → JSON/CSV 到 OSS → 记录交付信息
安全默认：到期未决策 = 自动续留 1 年（绝不因无人处置而删数据）
```

## 6. 存量数据上线仪式（2024 年及更早数据）

1. **摸底**：上线首个任务只读输出各表年份分布，人工确认
2. **回填起算时间**：有 createdAt/closedAt 按实际回填 retainUntil；无时间字段按最后更新兜底；无法确定进未知年龄桶人工复核
3. **分批处理**：按月分批，每天一批，绝不全量一次性搬
4. **干跑一周**：dry-run 只统计不动数据，数字一致后开启真实归档
5. **可逆**：归档标记可撤回；批量动作前自动生成处理清单入审计
